Agenda

Build a Deep Research Board

Learn mods by building something you already understand: a research progress board.

Path 20-slide path

  • • Mental model: plugins, hooks, three moves.
  • • Build: Deep Research Board (observe + UI).
  • • Stretch: gate weak answers; open a sources pane.
Concept

What Is a Mod?

A small JavaScript or TypeScript plugin that lives inside your Claude Code session.

Mod In plain words

  • • Watch what Claude is doing (tools, turns).
  • • Change prompts or block unsafe/weak steps.
  • • Draw a live board in the terminal UI.
Compare

Why Not Just Settings?

Settings hooks fire a shell per event. Mods stay loaded and can keep score.

Why For a research agent

  • • Remember how many sources you already have.
  • • Redraw a board after every fetch.
  • • Open a pane or register /research.
Structure

Anatomy of a Mod

Same shape as any Claude Code plugin — one module does the work.

Parts Required pieces

  • • plugin.json — name and description.
  • • hooks.json — points at research-board.mjs.
  • • register(on) — attach observe / rewrite / answer hooks.
API Core

Observe · Rewrite · Answer

Every hook either watches, changes the event, or stops it.

Moves Research examples

  • • Observe — count WebFetch / Read as sources.
  • • Rewrite — inject a research checklist into the prompt.
  • • Answer — deny a final conclusion until sources ≥ 5.
Example

Deep Research Board

A live scoreboard above the prompt while Claude researches.

Board What you see

  • • Question + status (idle / researching / ready).
  • • Sources found vs target (e.g. 5/5).
  • • Latest domains + claim count.
Shortcut

Let Claude Write the Mod

You do not need the API first — describe the board in plain language.

Flow Say this

  • • "Make a mod: Deep Research Board above the prompt."
  • • "Count WebFetch/Read as sources; show 5/5 target."
  • • Allow hot reload; tweak rules in chat.
Step 1

Create the Folder

Claude Code 2.1.287+. Same plugin layout as the official guide.

Setup Checklist

  • • claude --version ≥ 2.1.287.
  • • Name the plugin deep-research-board.
  • • hooks.json → ./research-board.mjs.
Step 2

Draw Above the Prompt

Hook ui.render on AbovePrompt — empty by default, perfect for a board.

UI First win

  • • $.ui.resolve(e) gives Box and Text.
  • • Show a static line: RESEARCH · 0/5 sources.
  • • claude --plugin-dir ./deep-research-board.
Step 3

Observe Tool Calls

When Claude fetches a page, add it to the board state.

State Pattern

  • • on("tool.call") for WebFetch / Read / Bash curl.
  • • Push {url, title} into $.state.board.sources.
  • • Hot reload wipes module vars — keep score in $.state.
Step 4

Prompt + Live Board

Rewrite the prompt to force a research checklist; redraw after each fetch.

Loop Put together

  • • prompt.submit — append: find ≥5 sources, cite, then conclude.
  • • ui.render — paint question / sources / latest domains.
  • • Pass with next(e) when the board is empty.
Step 5

Validate & Test

Prove the board counts sources without a live research session.

QA Quality bar

  • • claude plugin validate ./deep-research-board
  • • Test: stub three WebFetch calls → sources === 3.
  • • Assert the band text includes 3/5.
Step 6

Share via Marketplace

Ship like any plugin — marketplace add, install, reload.

Ship Install path

  • • /plugin marketplace add your-org/my-mods
  • • /plugin install deep-research-board@my-mods
  • • Only install mods you trust — they run with Claude's access.
Stretch A

Answer Move: Min Sources

If Claude tries to conclude with fewer than 5 sources, deny and nudge.

Guard How it feels

  • • Detect "final answer" / conclusion turns.
  • • return { deny: "Need 2 more sources…" }.
  • • When sources ≥ 5, call next(e) and let it write.
Stretch B

Open /research Pane

Register a slash command that lists every source collected this session.

Pane Observe + command

  • • $.command.register({ name: "research" }).
  • • command.run → $.ui.open sources list.
  • • Same $.state.board the band already uses.
Craft

Four Habits

Same habits as the official guide — applied to the research board.

Habits Keep these

  • • Lean on .claude-plugin/types/ Claude writes.
  • • Read hasSurvey / bodyColumns from e.props.
  • • Scoreboard in $.state; use --debug if the board vanishes.
